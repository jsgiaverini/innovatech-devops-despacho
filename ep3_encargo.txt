1.  Instrucciones generales  
Descripción  
▪ La Evaluación Parcial N°3 consiste en una práctica avanzada de orquestación y automatización en la nube , donde cada dupla 
deberá: 
o Configurar un clúster de contenedores en AWS ECS o AWS EKS. 
o Desplegar servicios Frontend y Backend utilizando imágenes almacenadas en ECR. 
o Implementar autoscaling y networking asociado. 
o Crear un pipeline CI/CD con GitHub Actions que automatice la liberación de software hacia el clúster (build → push → 
deploy). 
o Evaluar métricas, tiempos, logs, funcionamiento y comunicación entre servicios. 
o Presentar y defender la arquitectura, el despliegue y el pipeline implementado. 
▪ La evaluación combina ejecución práctica (encargo grupal) y una defensa técnica individual. 
 
Contexto del caso :

▪ Automatizar completamente los despliegues desde GitHub a través de GitHub Actions. 
▪ Garantizar que la aplicación pueda escalar, autorecuperarse, registrar logs, balancearse y mantenerse disponible ante cambios o 
fallos. 
▪ Se debe utilizar únicamente ECS o EKS, según la arquitectura seleccionada por la dupla.

Ítem I: Consideraciones para el Encargo 
•1. Configuración del Clúster en AWS (IE3) 
• La dupla debe demostrar: 
• Creación de clúster ECS/EKS. 
• Configuración de nodos/Capacity Providers/Fargate. 
• Configuración de VPC, subredes y Security Groups. 
• Roles IAM requeridos (EKS node role, ECS task role, execution role). 
• Descripción y justificación de la arquitectura. 
 
• Despliegue de Servicios Frontend + Backend (IE4) 
La dupla debe exponer: 
• Task Definition o Deployment configurado. 
• Uso de imágenes desde Amazon ECR. 
• Variables de entorno cargadas correctamente. 
• Balanceo mediante Application Load Balancer si corresponde. 
• Acceso por URL pública al Frontend. 
• Comunicación correcta Front → Back vía DNS interno/ALB/Service. 
 
• Configuración de Autoscaling (IE5) 
Se debe incluir: 
• ECS: Target Tracking (CPU/Memory). 
• EKS: Horizontal Pod Autoscaler (HPA). 
• Capturas de configuración. 
• Justificación del valor elegido (ej. 50% CPU).

• Pipeline CI/CD (IE6 y IE7) 
La dupla debe demostrar: 
• Frontend accesible públicamente.

Presentación técnica  
Debe explicar: 
• Arquitectura final. 
• Roles, redes, autoscaling, balanceadores. 
• Métricas de pipeline (tiempo, fallos, logs). 
• Problemas encontrados y cómo se resolvieron.
